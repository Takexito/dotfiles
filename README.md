# dotfiles

Конфигурация, которая должна быть одинаковой в каждом dev-контейнере.

Родилась из конкретной проблемы: контейнеры стартуют голыми, в них нет ни
`user.name`, ни `user.email`, поэтому `git commit` внутри падает с
`Author identity unknown`. Заодно там не было и pre-commit хука, проверяющего
секреты.

## Что внутри

| Путь | Что делает |
|---|---|
| `git/config` | идентичность, `pull.rebase`, `push.autoSetupRemote`, `rerere`, алиасы |
| `git/ignore` | глобальный gitignore: `target/`, `.venv/`, `node_modules/`, мусор ОС |
| `git/hooks/pre-commit` | ищет секреты через `gitleaks` |
| `shell/rc.sh` | алиасы, история, приглашение с именем проекта и веткой |
| `install.sh` | идемпотентная установка |

## Установка

```sh
./install.sh
```

Ничего не затирает: подключается к существующим `~/.gitconfig` и `~/.bashrc`
через `include.path` и `source`, а не подменяет их. Повторный запуск безопасен.

В dev-контейнерах разворачивается автоматически — `newdev` передаёт репозиторий
в `devcontainer up --dotfiles-repository`.

## Границы

Здесь только то, что осмысленно **и на хосте, и в контейнере**. Намеренно не
входит:

- **Секреты и токены.** Репозиторий публичный.
- **Бинарники.** `gitleaks`, `rg`, `fd` ставятся образом контейнера. Хук
  `pre-commit` при отсутствии `gitleaks` громко предупреждает, но не блокирует
  работу — молчаливый пропуск проверки опаснее её отсутствия.
- **Хостовые пути.** `~/.bashrc` на машине разработки завязан на шимы `mise`,
  которых в контейнере нет.
- **Доступ к приватным репозиториям GitHub.** Это отдельная задача: `gh` плюс
  общий том с авторизацией, а не файл конфигурации.
